# External query-tool gateway

**Router:** `apps/api/app/routers/query_tools.py`  
**Audience:** Admins publish and grant; external AI developers discover and invoke.

## Purpose

A separate, external-facing registry: fixed read-only SQL/MCP query templates published as REST/OpenAPI/MCP tools for external AI clients (VS Code, Google ADK, other MCP clients), with per-client credentials and grants.

## Status notes

Callers never receive database credentials and never submit SQL or identifiers — only typed parameter values against a fixed, reviewed template.

Full lifecycle now closed: draft → tested (`/test`) → published (`/publish`) → retired (`/retire`), shown via a status pill in the gateway list. The wizard (`relation-options` + `wizard/preview`) is a real guided multi-step flow in the UI (pick relation → template → column → generate draft), not just starter templates. What's still open: no in-app search/filter-by-tag/LOB/owner control for the gateway list itself — see `IMPLEMENTATION_STATUS_MATRIX.md` §2.

**Two consumers, one registry.** A published `QueryTool` has always been reachable by *external* accessors (`ExternalClient` + `QueryToolGrant`, over `/external/v1/*` and `/mcp`). As of Aug 8, 2026 it is also reachable by *internal* DataPilot agents: `AgentDefinition`/`AgentVersion.query_tool_names` binds an agent to published query tools in its project, and the bounded orchestration loop (`temporal_activities._execute_bound_tools`) invokes them the same way the external gateway does — same read-only enforcement, same PII masking, same governance logging — just without an `ExternalClient`/rate limit in the path (internal calls are budgeted by the run's ≤12-tool-call cap instead). See [`agents.md`](./agents.md) for the agent-side contract. Previously, a SQL tool generated by the wizard and verified/published had no path into agent execution at all; that gap is closed.
